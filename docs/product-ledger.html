1 · Final goal

Give any agent a small, inspectable toolbox—without giving it the keys to everything.

Any person can define a readable Angel over connected Apps, run the same immutable policy locally or on managed or self-hosted infrastructure, and check how each call was bounded—while provider credentials stay outside the agent.

G01

Angel is a toolbox, never an actor

Only the user’s agent initiates an MCP call; Angel has no loop, intent, scheduler, or mailbox.

G02

Policy stays portable and readable

ANGEL.yaml contains charter and policy, never target, Account, Connection, or credential identity.

G03

Builds are deterministic and secret-free

The client compiles canonical immutable bytes; no server builds user source.

G04

Authority is explicit

Absent tools do not exist; guards bind arguments; anything unexecutable cannot publish.

G05

Two gates fail closed

Gateway and Broker decide independently; disagreement or partial install produces no provider call and no fallback.

G06

Credentials go in and never come out

Only the unaddressable Broker can lease provider credentials; APIs return safe summaries only.

G07

Other tenants do not exist

Cross-Account resources are indistinguishable from absent ones; selectors choose one Connection and omission never fans out.

G08

The same trust object runs locally and remotely

Bundle digest and engine pin travel through publish, verify, receipts, and replay; the product states where proof ends.

G09

Release defaults stay simple and safe

Bare publish means production; preview is explicit, isolated, and exact-byte promotion never rebuilds.

G10

Owners control the full lifecycle

Keys are shown once and recoverable by safe rotation; pause only removes; deletion is deliberate, total, and self-service.

G11

Trust evidence is public without private identity

Every live Angel exposes a secret-free trust page and review bundle, never credentials or Connection identity.

G12

One product spans CLI, browser, and agent

The surfaces share one policy, compiler, artifact, and job model; public docs suffice and human auth/consent remain human.

G13

Local use is independent; hosting is optional

Local create/build/connect/serve needs no Angel Cloud account; managed and self-hosted custody stay separate.

G14

Source and deploy topology stay bounded

One repo may hold many packages/apps, but core/CLI packages, deployables, Cloudflare accounts, bindings, and secrets remain separate.

3 · Proposed next goal · not approved

P0 — Monorepo and release integrity

One reviewed change can update core, CLI, hosted apps, docs, and tests without weakening package, deploy, account, binding, or secret boundaries.

Deliverables

  • Rename angel-cloud to angelmcp in place.
  • Audit then import angel-core history under packages/core.
  • Keep separate core and CLI packages; separate Control, Gateway, Broker, www, and docs apps.
  • Use pnpm, one lockfile, and workspace:* internally.
  • Make the monorepo the only source for examples and docs.
  • After O1 closes, publish the public CLI with npm provenance; test the last registry tarball outside the workspace.
  • Keep the forkable starter only as a generated/external consumer; archive private scratch.

Must not change

  • No auth, OAuth, policy, runtime authorization, route, provider, or UX redesign.
  • Correct stale docs or displayed commands only when they contradict shipped behavior; add a regression test for each correction.
  • No Cloudflare production mutation or secret movement. Public deployed-link proof starts in P1.
  • No collapse of deployables, Cloudflare accounts, bindings, or custody.
  • No v2.1 feature work hidden inside migration.

Exit proof

pnpm run verify:phase0 from a fresh clone: history/secret audit, full checks, package tarballs, external registry consumer, tested docs examples and links, shipped-decision sweep, and all Worker dry-runs pass. A before/after runtime behavior matrix has zero differences.

Blocking: O1 (public package/install identity) and explicit owner approval of P0 after ledger review.

6 · Changes since the APRD review

What moved, without being lost

Changed now

  • Product Ledger replaces ROADMAP as the plan of record.
  • Option A monorepo migration is explicit P0.
  • Definitions of done become commands from clean environments.
  • Every decision requires a CLI/docs/www/test sweep.
  • Every dogfood closes with ledger reconciliation.

Scope reduced

  • The old all-in-one v2.1 is split into P1 local and P2 managed proofs.
  • Browser/mobile authoring stays visible in P3.
  • Provider breadth and hosted verified OAuth move to P4.
  • Catalog/sharing/self-hosting move to P5.
  • Multiplayer remains P6.

Newly surfaced

  • Package identity and installer are still open.
  • Headless Linux OAuth/storage needs a real spike.
  • Local/cloud consent syntax is unresolved.
  • Magic-link expiry contradicts the raw requirement.
  • Public provenance and Account deletion need exact contracts.

Explicitly not next

  • No product feature work inside P0.
  • No broad UI redesign without a designer.
  • No billing before beta evidence.
  • No self-hosting claim before a supported clean room.
  • No second source of truth in a starter or catalog.
7 · Standing operating rule

The ledger is the plan of record

Before a milestone

Interview → update goal, roadmap, and four-surface job map → reconcile learnings → close next-blocking decisions → approve one outcome and its proof command.

During a milestone

Every deliverable links to a guarantee and proof. A scope cut changes the ledger in the same PR. No silent debt.

After a spike or dogfood

Tag the run, save evidence, add findings, assign every disposition, and show the delta before planning more work.

At release

Run the clean-environment command. Sweep CLI, docs, www, tests, and deployed links. Only then mark the milestone done.
