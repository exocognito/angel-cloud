Goals G1–G7

IDStatement (condensed)Status
G1Least authority, compiled: only allowlisted canonical operations with argument guards; enforcement compiled from reviewed source — never a model, prompt, or runtime config.observed
G2M2: run one person's real daily workflows across providers. Gmail write with real guard enforcement first, then Maps, then differently shaped integrations — each adapter ships with guard enforcement, deterministic CI, and live credentialed acceptance.change
G3angel publish goes source → live production endpoint in one step. Preview is opt-in (--preview) and binds its own Connections (PD 0003 + PD 0005). Server half built: deployProduction installs a published Version directly, deployPreview refuses an unbound preview deploy.change — CLI only
G4An agent with only the public docs (docs.angelmcp.ai: index, llms.txt, SKILL.md) can take a user zero → live Angel through the management API. Install paths plural: npm now, curl installer next; repo clone is never the interface.observed docs (#4) · change host (#6), curl, walk (#5)
G5Every Angel has one canonical coordinate @handle/angel and a public page at that coordinate, readable without key or login (PD 0001, PD 0002).observed coordinate · change page (#11)
G6Two independent gates evaluate every executed call; each writes a hash-chained receipt; success requires convergence. Deployments are digest-pinned: production runs byte-for-byte what was published.observed
G7Directional only, not normative: M3 stranger self-serve signup/billing; M4 Personal and Family Account shapes. Sequenced strictly after G2.directional

Non-goals (summary): no code-execution engine (platform accepts canonical secret-free artifacts, never source YAML); no authoring/publishing from the web UI; MCP is the only invocation surface (REST on api. reserved, not built); omission never means fan-out (ADR 0002); the Broker never gets a hostname; no per-Angel infrastructure (a fixed Worker set, constant as Angels multiply).

Invariants I1–I14 — what must never happen

IDNameStatement (condensed)StatusWhere enforced

Priority rules P1–P4 — conflict resolution

IDRuleOperational consequence
P1Fail closed beats availabilityEnforcement uncertainty (gate mismatch, custody failure, malformed provider result) refuses the call. Convergence failure = HTTP 500 / JSON-RPC −32603, and that status is intended.
P2Isolation beats convenience; convenience beats empty ceremonyCredential/environment isolation never traded for fewer steps (PD 0005). But a step that protects nothing is a defect (PD 0003): first publish goes straight to live.
P3Publish-time rejection beats runtime failureUnsupported operations fail at publish (registry); missing scopes fail at deploy (409 per bound operation, bindingOperationGaps at management.ts:747-770), not at the provider.
P4Document precedenceSpine > Evals > System diagram > Prototype > FAQ. The Angel Product Ledger owns sequence/status; ADR/PD index Status lines beat any individual record's prose (PD 0003 vs PD 0005 is the standing example).

S5 · Gateway → Broker (data plane) observed

The convergence contract: Gateway forwards its receipt's identity fields; the Broker re-evaluates from scratch and refuses on any mismatch (409 → agent sees 500/−32603). presentedKey is never forwarded.

InvokeRequest { runtimeId; input: GateEvaluationInput; expected: GateReceiptIdentity }
GateEvaluationInput { requestId; tool; arguments; connectionRef?; presentedKey? /* never set here */ }
GateReceiptIdentity = Pick<GateReceipt, "deploymentId"|"version"|"policyDigest"
  |"bindingsDigest"|"availabilityDigest"|"tool"|"connectionRef">

S6/S7 · Broker → Vault → Provider observed, including #10's configurable scopes

Lease inside the Broker only; refresh → pinned origin; the sealed HttpRequestTemplate is materialized (path traversal and non-scalars rejected) and executed — the Broker enumerates no operations. #10 shipped: the consent scope set is a Provider App property, the deploy-time floor is derived per bound operation from the adapter registry (bindingOperationGaps), and provider labels derive from the registry too. The compiled list survives only as DEFAULT_GOOGLE_PROVIDER_SCOPES, the fallback when a Provider App names none.

S8 · Anyone → public Angel page new (PD 0002 / #11)

Read-only, no auth, at the bare coordinate on the apex. Must have no path to Broker, custody, or keys (I14). Served by the future apex dispatcher; content shape deliberately open (FAQ). The only seam here still unbuilt. docs.angelmcp.ai is settled and its content ships (#4); the name waits on the zone move (#6).

Error reference

Policy denials (MCP)

Denials are HTTP 200 with isError: true and structuredContent.denial.reason:

ReasonMeaning
unknown_toolThe operation is absent from the deployed policy artifact.
connection_requiredMore than one Connection is eligible and angel_connection was omitted.
connection_unavailableThe selector is stale (pre-redeploy ref), unknown, or unbound.
connection_pausedThat tool + Connection tuple is paused.
tool_pausedThe tool has no active Connection.
guard_deniedAn argument guard rejected the call (e.g. a forbidden value).

Transport & platform (MCP surface)

Status / codeCause
401 / −32001Missing or wrong Angel key — checked before the body is read. A preview/staging key presented to production also 401s.
405 + Allow: POSTGET on the MCP endpoint — until the public page exists at the coordinate; then GET renders it, POST still invokes.
406Wrong Accept.
415Wrong Content-Type.
403Foreign Origin.
400Missing MCP-Protocol-Version after initialize; bad JSON.
404Absent route or resource — cross-Account lookups return the same 404 (I6).
500 / −32603"Angel gates failed to converge" — the intended fail-closed status (P1). No provider call was made.
−32003 familyProvider or custody failure — e.g. a revoked Connection (lease 404, or refresh-time invalid_grant → health flip + 500). Distinct from convergence failure.

Management (/v1 and dashboard actions)

StatusCause
400Artifact digest, canonical source, or sealed templates disagree with the registry at publish; unknown JSON keys (I11); invalid input; empty Idempotency-Key.
401Missing Access identity or bearer.
404Resource absent — or owned by another Account (I6: no existence signal).
409Stale expectedDigest; inactive stagedDeploymentId; binding a Connection missing a required scope (deploy-time, P3); Idempotency-Key reuse with different method/path/body; mutation during a pending availability repair (I4); delete of a live or pending production deployment without typed-slug confirmation; a binding naming operations absent from the deployed adapter registry.
501Provider App removal — not implemented.

Management errors share one shape: {"error":"<message>"} with the HTTP status. Provider and custody failures throw; the runtime never silently substitutes a fixture (I5, P1).

Build & release constraints

ConstraintDetail
Core package pin chainArtifact schema, compiler, registry, and CLI live in exocognito/angel-core; they reach angel-cloud only as the pinned npm package, currently @smcllns/angel-core@0.2.0. That CLI offers exactly build, publish (to preview, spelled staging) and deploy --prod. Publish defaulting to production, --preview, the typed share flag and angel delete all wait on one release — and the /v1 legacy dialect exists to keep 0.2.0 working until it lands. This is now the largest gap between the spine and the code.
/v1 exact-key parsingPinned CLIs parse /v1 responses with exact-key strictness. Never add a response field without a core release plan (management.ts strips grantedScopes for this reason).
runtimeId shape"${accountId}:${slug}:${environment}", built from the canonical environment. Handle resolution (#12) happens before Durable Object addressing — DO names never contain handles, gates and receipts were untouched by handle work, and a retired handle addresses the same object as the current one.
Digest computationThe artifact digest is computed over compiler-ordered JSON.stringify bytes — not re-canonicalized JSON. Same digest republished returns the same Version (I2).
Internal role tokensMust be non-empty and pairwise distinct; misconfiguration fails closed at boot.
Gate key routingKey hashes go to the gateway gate only; the broker gate rejects them. presentedKey is never forwarded across S5.
Infrastructure ceilingA fixed Worker set, constant as Angels multiply. The Broker is reachable only over service bindings — no hostname, ever.
Artifact intakeThe platform accepts canonical secret-free artifacts only; never source YAML, never a user's build (non-goal: no code-execution engine).

Suspicious — flagged, not classified

  • src/control.ts still ships legacy DemoControl emitting angelmcp.demo.v1; reachable from one test file only. Deletion candidate.
  • types/broker.d.ts is hand-written but labeled Wrangler-generated and omits CredentialVault from durableNamespaces; controlErrorResponse (src/workers/control.ts:600) is dead code. (ControlRequestEnv now carries the GATEWAY binding — that one is fixed.)
  • google-read-proof is excluded from the fixture-staleness check (scripts/check-fixture-staleness.ts lists the other four); digest verified only at acceptance-run time.
  • Revoked-Connection failures reach the agent by two paths (custody lease 404 vs refresh-time invalid_grant), both −32003-family; the asymmetry is undocumented.

Deliberately open do not decide unilaterally

  • Public page design (#11): content (guards? digest? Version?), public-by-default vs opt-in, preview pages, content negotiation vs split routes. Settle when the coordinate exists.
  • Handles: visible retirement of old handles; confusable lookalikes (rn/m, 1/l) — decide before public signup (M3).
  • Grammar growth: per-PR builds alongside preview; apex dispatcher shape; where control-plane paths live once REST invocation lands on api.; pinned @N reserved, deferred.
  • Rollback: by re-promotion only; no dedicated command. Any future rollout policy must still name immutable digests and explicit bindings (ADR 0003).
The dataroom is normative; where this page and the dataroom disagree, the dataroom wins.
