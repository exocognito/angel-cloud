# Angel Cloud v2.1 CLI user guide

Normative v2.1 command contract.

Target-state contract, not shipped current behavior. The current shipped manual
remains `docs/user-manual.md`; this guide defines what the v2.1 implementation
must support before the CLI-first golden path can close.

## Install the final v2.1 CLI

Install path:

```sh
pnpm add --global @smcllns/angel-core@v2.1
```

The package installs the `angel` binary on `PATH`; the resulting command is `angel`. After installation, all final user docs and examples invoke `angel`
directly.

Starting state for the golden path: a new project directory with no repository
clone, no `ANGEL.yaml`, no `angel.json`, no Account session, no local token, no
Connection, no Angel key, and no Gmail draft.

Human-only handoffs for the whole journey: email magic-link sign-in, Google
OAuth client setup where required, provider consent, and final Gmail draft
review. An agent may open the browser and prepare inputs, but the owner
authenticates, consents, and reviews the draft.

Out of scope for this v2.1 golden path: preview and promotion remain documented
as supporting shipped mechanics in the current [user manual](../user-manual.md#promote-the-exact-previewed-deployment);
key management and Angel delete remain current dashboard/API mechanics in the
[user manual](../user-manual.md#delete-an-angel); web authoring/publish parity
stays a later surface governed by [PD 0006](../product-decisions/0006-www-is-a-full-write-surface.md).

## angel account login

Purpose: signs the owner into Angel Cloud from the CLI and binds the local
machine to one Account.

Syntax:

```sh
angel account login [--control https://control.angelmcp.ai] [--account <handle>]
```

Inputs: optional Control origin and optional Account handle. If omitted, the CLI
uses the production Control origin and asks the signed-in owner to choose from
their Accounts.

Outputs: browser URL, Account handle, local token label, expiry, and the
current Control origin. Bearer tokens are never printed.

Durable side effects: stores an Account-scoped management token in the OS
keychain and writes the selected Account handle into the local Angel Cloud CLI
profile.

Human-only handoffs: the owner opens the email magic link, completes browser
sign-in, and selects or confirms the Account.

Idempotency and retry: rerunning the command refreshes or reuses the Account
session for the same identity. A lost browser callback may be retried with a new
login nonce; no Angel, Connection, key, Version, deployment, receipt, or
provider object is created by login.

Failure boundaries: expired links, wrong identity, unavailable Control, bad
Account selection, and keychain write failure stop before any management
mutation or provider call.

Example:

```sh
angel account login --control https://control.angelmcp.ai --account acme-labs
```

## angel create

Purpose: scaffolds reviewable Angel source and a local deployment config for a
new Angel.

Syntax:

```sh
angel create <angel> --template <template> [--directory <path>]
```

Inputs: Angel slug, template name, and optional output directory. The v2.1
golden path template is `gmail-draft-without-send`.

Outputs: paths written, source summary, allowed tools, guards, required
provider scopes, and the owner review reminder.

Durable side effects: writes `angels/<angel>/ANGEL.yaml` and
`angels/<angel>/angel.json`. It does not create a cloud Angel or provider
Connection.

Human-only handoffs: the owner reviews and approves the complete source before
build, serve, publish, verify, receipt pull, or replay.

Idempotency and retry: rerunning with the same slug and unchanged generated
files is a no-op. If local files differ, the command refuses unless the owner
passes the explicit overwrite flag defined by implementation.

Failure boundaries: invalid slug, unknown template, existing divergent files,
unknown operations, malformed guards, forbidden `angel_connection`, and source
that cannot compile fail locally before network or provider work.

Example:

```sh
angel create gmail-draft-assistant --template gmail-draft-without-send
```

## angel apps connect

Purpose: creates or refreshes an Account-owned provider Connection and records
the owner-approved nickname for later binding.

Syntax:

```sh
angel apps connect google --nickname <nickname> --scopes <scope-list> [--app <provider-app-name>]
```

Inputs: provider, Connection nickname, comma-separated scope set, and optional
Provider App name. The Gmail draft golden path uses `gmail.compose`.

Outputs: provider, Provider App summary, Connection nickname, provider identity
label, granted scopes, health, and the local binding update to apply.

Durable side effects: stores or refreshes a Google OAuth grant in Broker
custody, stores only safe summaries in Control, and writes the nickname into
the local `angel.json` production binding selected by the owner.

Human-only handoffs: the owner creates or confirms the OAuth client when using
the own-client tier, completes Google consent, and approves the nickname.

Idempotency and retry: retrying the same nickname and provider identity refreshes
the existing Connection. Reusing a nickname for a different provider identity or
different Provider App fails until the owner renames one side.

Failure boundaries: missing login, missing OAuth client, declined consent,
insufficient scopes, unhealthy grant, nickname collision, Account mismatch, and
custody write failure fail before publish or any provider tool call.

Example:

```sh
angel apps connect google --nickname personal-gmail --scopes gmail.compose --app owner-google
```

## angel build

Purpose: compiles Angel source into the immutable, secret-free bundle that local
serve and cloud publish both run.

Syntax:

```sh
angel build <angel> [--out <directory>]
```

Inputs: Angel slug and optional output directory.

Outputs: bundle path, digest, canonical source path, required bindings, required
scopes, and engine pin.

Durable side effects: writes `build/angel.version.json` and
`build/angel.version.sha256` under the Angel directory or selected output
directory.

Human-only handoffs: none at runtime; the owner must already have approved the
source.

Idempotency and retry: the same source, compiler, and engine pin produce the
same bytes and digest. Rebuilding an unchanged Angel overwrites the same local
build outputs only.

Failure boundaries: malformed YAML, duplicate tools, unknown registry
operations, invalid guards, unsupported composed children, source-policy
mismatch, and engine incompatibility fail locally before management or provider
work.

Example:

```sh
angel build gmail-draft-assistant
```

## angel serve

Purpose: serves the built Angel locally as a real MCP endpoint that uses the
same bundle and engine decision logic as production.

Syntax:

```sh
angel serve <angel> [--bundle <path>] [--port <port>] [--connection <nickname>]
```

Inputs: Angel slug, optional bundle path, port, and local provider Connection
nickname.

Outputs: local MCP URL, bundle digest, engine pin, enabled tools, provider
identity labels, and keychain token label.

Durable side effects: stores local OAuth tokens in the OS keychain when the
owner completes provider consent. It does not mutate cloud state, deployments,
production keys, or receipt chains.

Human-only handoffs: the owner completes any local provider OAuth consent.

Idempotency and retry: rerunning with the same bundle starts the same endpoint
semantics on the selected port. If the port is taken, the CLI fails unless the
owner selects another port.

Failure boundaries: missing bundle, digest mismatch, missing local token,
missing scope, bad port, unsupported provider operation, and provider consent
failure stop before cloud work. Local serve never uses hosted credentials or a
fixture fallback.

Example:

```sh
angel serve gmail-draft-assistant --port 7423
```

## local MCP `tools/list` / `tools/call`

Purpose: proves the local runtime exposes and enforces the same MCP tool
contract the built bundle declares.

Syntax:

```text
POST http://localhost:<port>/mcp
MCP methods: initialize, notifications/initialized, tools/list, tools/call
```

Inputs: MCP streamable HTTP requests with `Content-Type: application/json`,
`Accept: application/json, text/event-stream`, and
`MCP-Protocol-Version: 2025-06-18` after `initialize`.

Outputs: `tools/list` returns only deployed tools and their input schemas.
`tools/call` returns provider data or a policy denial, plus local decision
evidence sufficient to compare with production replay.

Durable side effects: only provider-side effects allowed by the local owner's
token and policy. For the golden path, the local call may create a Gmail draft
only after the owner approves using the local token for that test.

Human-only handoffs: final review of any real provider draft or other write.

Idempotency and retry: MCP request IDs identify client requests, but provider
idempotency depends on the provider operation and arguments. Retrying a draft
call can create a second draft unless the test uses a generated idempotency
marker and verifies only one matching draft.

Failure boundaries: wrong MCP headers, unsupported protocol version, unknown
tool, stale `angel_connection`, missing scope, guard denial, digest mismatch,
and provider failure return a structured error and do not fall back to fixtures.

Example:

```json
{"jsonrpc":"2.0","id":"draft-local","method":"tools/call","params":{"name":"gmail.users.drafts.create","arguments":{"message":{"raw":"<base64url-rfc822>"}}}}
```

## angel publish

Purpose: builds the Angel, publishes the immutable Version, deploys it to
production by default, and prints the production call coordinates.

Syntax:

```sh
angel publish <angel> [--preview] [--share-production-credentials]
```

Inputs: Angel slug, local `angel.json`, Account login profile, and optional
preview flags. Bare publish means production.

Outputs: bundle path, digest, engine pin, Version number, production MCP
endpoint, trust-page URL, first-time preview and production Angel keys, and
whether the publish was a no-op replay of an existing Version.

Durable side effects: ensures the cloud Angel, publishes a digest-addressed
Version, resolves production bindings by nickname, installs Broker then
Gateway production gates, and stores only key hashes. On first creation, it
prints plaintext keys once.

Human-only handoffs: none during the command; the owner already approved
source and Connections.

Idempotency and retry: repeating an unchanged publish returns the same Version,
digest, endpoint, and existing keys by fingerprint only. The CLI reuses the same
management idempotency key when retrying a lost response for a logical mutation.

Failure boundaries: missing login, missing or unhealthy Connection, missing
scope, binding mismatch, digest mismatch, engine mismatch, Account mismatch,
pending repair conflict, idempotency-key reuse with different input, and gate
install divergence fail before production provider work.

Example:

```sh
angel publish gmail-draft-assistant
```

## angel verify

Purpose: checks that the production deployment runs the same digest and engine
pin as the local bundle, then states the trust boundary.

Syntax:

```sh
angel verify <angel> --production [--bundle <path>]
```

Inputs: Angel slug, production environment flag, and optional bundle path.

Outputs: local digest, remote digest, local engine pin, remote engine pin,
production MCP endpoint, receipt-tail summary, and the sentence:
`Everything attestable is client-checkable; execution is trusted, bounded by replay.`

Durable side effects: none. Verification is read-only.

Human-only handoffs: none.

Idempotency and retry: safe to rerun. A network loss can be retried without
changing any Angel, Version, deployment, key, Connection, receipt, or provider
object.

Failure boundaries: missing login, no production deployment, digest mismatch,
engine mismatch, unavailable artifact bytes, wrong Account, and malformed
remote metadata fail the command and print no stronger claim.

Example:

```sh
angel verify gmail-draft-assistant --production --bundle build/angel.version.json
```

## angel receipts pull

Purpose: fetches an anchored, inclusive sequence range of production receipts
for local audit and replay.

Syntax:

```sh
angel receipts pull <angel> --production --from <sequence> --to <sequence> --out <path>
```

Inputs: Angel slug, production environment, inclusive starting sequence,
inclusive ending sequence, and output path.

Outputs: NDJSON file path, first sequence, last sequence, count, first
`previousHash`, last `hash`, bundle digest, engine pin, and endpoint identity.

Durable side effects: writes the selected receipt range to the requested local
path. It does not mutate cloud receipts or provider state.

Human-only handoffs: none.

Idempotency and retry: safe to rerun for the same range and output path. If the
existing file has identical bytes, the command reports a no-op. If it differs,
the command refuses unless the owner selects an explicit overwrite flag.

Failure boundaries: missing login, no production deployment, invalid range,
gap in receipt sequence, first receipt not extending the caller's remembered
tail, digest mismatch, engine mismatch, output path conflict, and Account
mismatch fail without provider calls.

Example:

```sh
angel receipts pull gmail-draft-assistant --production --from 128 --to 151 --out receipts/production-128-151.ndjson
```

## angel replay

Purpose: re-runs recorded decisions locally against the same bundle and reports
whether cloud and local decisions match.

Syntax:

```sh
angel replay <angel> --receipts <path> --bundle <path> [--fail-on-tamper]
```

Inputs: Angel slug, receipt NDJSON path, bundle path, and optional tamper-fail
flag.

Outputs: checked count, first and last sequence, digest comparison, engine-pin
comparison, decision comparison, argument-digest comparison, and first mismatch
with sequence and field path.

Durable side effects: none unless the owner chooses an explicit report output
flag. Replay is local and read-only.

Human-only handoffs: none.

Idempotency and retry: safe to rerun. The same receipt file and bundle produce
the same replay result.

Failure boundaries: malformed NDJSON, chain break, digest mismatch, engine
mismatch, missing arguments digest, local policy divergence, and deliberate
tamper fail locally. Replay never calls a provider.

Example:

```sh
angel replay gmail-draft-assistant --receipts receipts/production-128-151.ndjson --bundle build/angel.version.json --fail-on-tamper
```

## production MCP `tools/list` / `tools/call`

Purpose: lets the owner's agent call the production Angel through the public MCP
coordinate with only the production Angel key.

Syntax:

```text
POST https://mcp.angelmcp.ai/@<handle>/<angel>
Authorization: Bearer <production Angel key>
MCP methods: initialize, notifications/initialized, tools/list, tools/call
```

Inputs: production Angel key, MCP streamable HTTP requests, and tool arguments.
For the golden path, the allowed call is `gmail.users.drafts.create`; a send
attempt uses `gmail.users.messages.send` and must be absent.

Outputs: `tools/list` returns only production tools with active Connections.
`tools/call` returns provider data and two agent-safe receipts, Gateway and
Broker, each carrying `sequence`, `previousHash`, `hash`, `argumentsDigest`,
bundle digest, engine pin, and gate identity. A send attempt returns
`unknown_tool`.

Durable side effects: the allowed draft call creates a Gmail draft and appends
Gateway and Broker receipts. Denied, unknown, unauthenticated, malformed, or
divergent calls create no provider side effect.

Human-only handoffs: the owner reviews Gmail and confirms a draft exists and no
sent message exists.

Idempotency and retry: MCP transport retry can repeat provider writes unless
the generated test embeds a unique marker and proves there is exactly one
matching draft. Receipt sequence and hash anchors make repeated calls visible.

Failure boundaries: wrong key, unknown handle, bad content negotiation, bad
content type, unsupported protocol version, bad Origin, unknown tool, stale
Connection ref, missing scope, guard denial, gate divergence, digest mismatch,
and engine mismatch fail before provider work except for failures returned by
the provider after an allowed call reaches it.

Example:

```json
{"jsonrpc":"2.0","id":"draft-production","method":"tools/call","params":{"name":"gmail.users.drafts.create","arguments":{"message":{"raw":"<base64url-rfc822-with-unique-marker>"}}}}
```
