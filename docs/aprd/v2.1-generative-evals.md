# Angel Cloud v2.1 generative eval specification

Target-state v2.1 eval contract.

This specification defines generative end-to-end evals for the v2.1 golden path.
The test-generating LLM must generate unseen names, source, policies, arguments,
Accounts, Connections, and mutations for each run. The generated E2E test file itself must be saved as evidence, together with its execution transcript and
observable system artifacts.

Global anti-hard-code rules:

- The test-generating LLM must generate unseen names, source, policies, arguments, Accounts, Connections, and mutations.
- A pass condition may not rest only on known fixture names.
- A pass condition may not rest only on static output strings.
- A pass condition may not rest on mocked provider success.
- Deterministic provider seams may be used for failure injection and ordinary
  CI, but the grader must inspect real platform state, receipts, digests,
  generated source, generated arguments, and provider-call counters.
- Each generated test must save its source file, random seed, generated
  `ANGEL.yaml`, generated `angel.json`, command transcript, MCP transcript,
  receipt files, replay output, and grader report.
- Email magic links are single-use and expire exactly 600 seconds after server-side commit; generated boundary and replay cases must prove it.
- Provider consent requires exactly one of `--local` or `--cloud`. Local grants use the Angel-owned encrypted vault; cloud grants use Broker custody; generated cases prove no cross-mode inspection or fallback.
- Replay tamper detection is mandatory. Generated tamper cases run bare `angel replay`, require a nonzero exit, and prove zero server, credential-store, network, and provider access.

## docs-only fresh-machine journey with a newly generated Angel

Input grammar:

```text
angel_slug ::= <lowercase noun>-<lowercase verb>-<4 random base32 chars>
template ::= "gmail-draft-without-send" | generated direct Google policy
owner_handle ::= <lowercase handle not present in seed fixtures>
subject_marker ::= "angel-v21-" <uuid>
body_marker ::= "generated-docs-only-" <uuid>
```

Degrees of freedom: choose a fresh slug, handle, subject marker, body marker,
output directory, port, and whether the policy comes from the template or from a
fresh direct source with the same safety property.

Unseen requirement: no generated slug, handle, marker, path, Account, or
Connection nickname may equal a committed fixture, example value, or previous
eval run.

Observable real-system evidence: install transcript from public docs,
`angel account login`, `angel create`, separate `angel apps connect --local` and
`angel apps connect --cloud` commands, `angel build`, `angel serve`, local MCP transcript, `angel publish`, `angel verify`, production
MCP transcript, `angel receipts pull`, `angel replay`, local build outputs,
production endpoint, receipt range file, and saved generated E2E test file.

Semantic/property grader: passes only if a fresh machine can complete the
journey from public docs, a separate local run passes while Angel Cloud is
unavailable and no Account login exists, custody stays separate across local and
cloud modes, the local grant survives a process restart only through the
encrypted vault, the built digest equals the verified production
digest, `tools/list` exposes the generated allowed tools and omits forbidden
ones, the production call creates the intended side effect, receipt range
anchors are continuous, replay matches, and all human-only handoffs are logged
without exposing secrets.

## novel generated policies and guards

Input grammar:

```text
policy ::= direct_policy | composed_policy
direct_policy ::= tools: 1..5 generated operations with optional guards
guard ::= pin(field,value) | forbid(field) | forbiddenValues(field, values)
allowed_call ::= operation in policy with generated allowed arguments
forbidden_call ::= absent operation | guarded operation with rejected arguments
```

Degrees of freedom: choose operations from the reviewed registry, guard fields,
pin values, forbidden values, argument shapes, Connection cardinality, and
whether the policy is direct or composed from generated child Angels.

Unseen requirement: generated operation sets, guard values, argument values,
Connection nicknames, and composed child names must not match committed
examples. At least one allowed and one forbidden call must be novel per run.

Observable real-system evidence: generated source, compiled artifact,
`tools/list` schema, allowed call receipts, forbidden call receipts or
`unknown_tool`, provider-call counter, and saved generated E2E test file.

Semantic/property grader: passes only if allowed calls reach the provider once,
guard-denied calls return semantic denials with receipts and zero provider
calls, absent operations return `unknown_tool`, pin guards override or bind the
argument as specified, and Connection selection never fans out.

## local/cloud artifact and decision parity with tamper detection

Input grammar:

```text
bundle_case ::= generated Angel source + production publish
receipt_range ::= independent Gateway range + independent Broker range, each length >= 2
chain_case ::= Gateway-only denial before a later allowed call with a Broker partner
tamper ::= flip digest | flip engine pin | delete arguments | edit original arguments | edit argumentsDigest | break previousHash | edit decision
```

Degrees of freedom: choose source shape, allowed operation, argument payload,
independent Gateway and Broker anchors and range lengths, denial position,
tamper type, tamper position, and whether tamper affects artifact bytes or
receipt bytes.

Unseen requirement: the internal grader first freezes a repository-derived
exclusion set, then launches a separate outside candidate. The outside candidate
sees public surfaces and generated inputs only, with no repository, fixtures, or
workspace links. Its source names, arguments, receipt ranges, and tamper edits
must be absent from the frozen exclusion set and prior runs.

Observable real-system evidence: local bundle, production artifact metadata,
MCP receipts, separate Gateway and Broker `angel receipts pull` outputs,
untampered `angel replay` output, Gateway-only denial evidence, tampered receipt
or bundle file, tamper-detection output, and saved generated
E2E test file.

Semantic/property grader: passes only if local build digest and engine pin match
production before tamper, each gate chain extends its own trusted anchor, the
Gateway-only denial needs no Broker record, the later allowed call correlates an
agreeing pair by request ID, local and cloud decisions replay to the same
semantic result, each deliberate tamper makes bare `angel replay` exit nonzero and name the
field and sequence; missing original arguments and edits whose recomputed digest
differs from `argumentsDigest` also hard-fail before decision replay; and replay
never starts a server, reads credentials, uses network, or calls a provider.

## account isolation, idempotent retry, and zero provider calls on failure

Input grammar:

```text
account_pair ::= owner_account + stranger_account
mutation ::= publish | connect | delete | key_rotation | availability_change
retry ::= same_idempotency_key_same_body | same_idempotency_key_different_body | new_key_same_body
failure ::= wrong_account | wrong_key | missing_scope | guard_denied | gate_divergence | pending_repair_conflict
```

Degrees of freedom: choose two generated Accounts, Angel slugs, Connection
nicknames, mutation types, retry ordering, failure injection point, and provider
operation under test.

Unseen requirement: Account handles, Angel slugs, keys, idempotency keys,
mutation bodies, and failure inputs must be fresh for each run.

Observable real-system evidence: management API transcript, CLI transcript,
MCP transcript, idempotency records, Account readbacks, receipt counts,
provider-call counters, and saved generated E2E test file.

Semantic/property grader: passes only if cross-Account reads and mutations
return the documented isolation status, identical mutation retries return the
same committed result, same-key different-body retries fail with conflict
before mutation, and every selected failure class proves zero provider calls.

## public review summary privacy, stability, and HTML/JSON parity

Input grammar:

```text
public_case ::= generated low-entropy charter + generated exact guards + generated operation set
version_pair ::= first published Version + changed second Version
leak_probe ::= nonce | raw digest | exact source | exact guard | scope | binding | identity | deployment metadata
```

Degrees of freedom: choose low-entropy charter and guard values, operation names,
guard presence, source shape, Version changes, response order, unknown keys, and
one field from every forbidden leak class.

Unseen requirement: the internal grader first freezes a repository-derived
exclusion set, then launches a separate outside candidate. The outside candidate
sees public surfaces and generated inputs only, with no repository, fixtures, or
workspace links. Its source, guards, operations, nonce probes, Version changes,
and leak probes must be absent from the frozen exclusion set and prior runs.

Observable real-system evidence: owner-only Version evidence, anonymous HTML and
JSON responses for both Versions, repeated responses for the first Version,
exact-key validation output, commitment verification output, same-Version public
surface crawl, forbidden-field leak scan, unknown-key failure, and the saved
generated E2E test file.

Semantic/property grader: passes only if HTML and JSON represent the same strict
`angel.public-review.v1` object; only schema, disclosure, artifact format and
commitment, canonical operation, and guard-presence fields appear; one Version's
commitment is stable across requests and differs from the changed Version; owner
evidence verifies each commitment; every same-Version public surface withholds
the raw digest; unknown keys fail; no leak probe appears; and the anonymous path
touches no key, cookie, Broker, credential, or private deployment state.

## live Gmail draft-without-send supplement

Input grammar:

```text
subject ::= "Angel v2.1 draft proof " <uuid>
recipient ::= owner-controlled test mailbox
body ::= generated paragraph with uuid marker
allowed_tool ::= gmail.users.drafts.create
forbidden_tool ::= gmail.users.messages.send
```

Degrees of freedom: choose subject marker, body marker, recipient alias,
draft payload shape, Account handle, Angel slug, and Connection nickname.

Unseen requirement: every marker, slug, nickname, and message payload must be
generated during the live run and absent from committed fixtures.

Observable real-system evidence: production MCP transcript, `tools/list`
showing `gmail.users.drafts.create` and omitting send, successful draft
response, Gateway and Broker receipts, Gmail UI or API confirmation that one
matching draft exists, Gmail UI or API confirmation that no matching sent
message exists, receipt pull, replay result, and saved generated E2E test file.

Semantic/property grader: passes only if the production Angel creates exactly
one matching Gmail draft, no matching sent message exists, `messages.send`
returns `unknown_tool`, receipts anchor the successful call, replay matches the
decision and argument digest, and the live proof is treated as a supplement to
the other eval families rather than the whole proof.
